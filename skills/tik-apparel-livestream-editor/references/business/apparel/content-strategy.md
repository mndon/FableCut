# 内容策略（内容逻辑与结构）

本文件是切片师在「阶段三 选句」时的业务指南：规定成片统一采用的内容策略（唯一一套，无多选项），描述内容逻辑、叙事结构、择优与排序。硬性红线（禁词清单、关联词、口误等数值与判定规则）的权威定义见 content-constraints.md，本文件不重复其条文，只在相关处用【红线：标签名】指向。

切片师读 `render_selection.py --index` 渲染的全量索引表后，先自己想清楚这条片子怎么讲，定出主线（观众看完要记住的那句话）与叙事逻辑（见「三、结构」），再在阶段三归纳本片内容维度（见下方「内容维度归纳规则」），再在阶段三合并询问里与用户对齐「想突出 / 想弱化哪些方面」（内容侧重，仅当用户未给任何内容方向、hosts.md 未预填且非新用户首次对话时发起）。用户的侧重作为选句与排序的首要优先级输入，仍须满足全部硬性红线。策略支持按内容逻辑重构排序。

## 一、内容取舍原则

目标：把视频剪成一条「让人看了想买、且买得明白」的带货短片——从用户能体验到的价值出发，讲清为什么值得买。

- 适用场景：电商带货、商品讲解、种草引流；目标是让观众产生「我也想要」的代入感，而非单纯罗列参数。
- 顺序：先激发欲望、再给理由。先让观众想要，呈现美、感受与场景；再讲为什么值得买，给细节、搭配、材质。不把参数与细节前置。
- 情绪价值：把商品放进具体生活场景来讲——讲「穿上它会成为什么状态、在什么场合更有底气」，而不只讲衣服本身的面料版型细节。
- 优先保留：用户可体验的感受/获益、具体使用场景、差异化价值、真实反馈。
- 可压低：与卖货弱相关的闲聊、重复寒暄、纯参数堆砌。
- 提炼原则：先提炼最想表达的意思、最吸引人的点；精简聚焦，宁可多切几段也不要一段塞太多。

## 二、内容维度归纳规则

本规则供阶段三内容侧重归纳与提问使用。切片师据本规则把本片转写聚为内容维度，先按下方「展示格式（提问前）」把归纳结果原样贴给用户看（中性罗列本片讲了哪些内容维度），再按「展示模板（内容侧重提问）」在阶段三合并询问里用 当前可用的用户提问工具 问用户想突出哪些；仅当用户未给任何内容方向、hosts.md 未预填且非新用户首次对话时才发起（给过方向、hosts.md 已预填或属新用户首次对话则整组跳过，不重复问）。用户的选择作为选句与排序的首要优先级输入；新用户首次对话不提问时，按默认维度取用——用户价值类优先，即上身效果与体感，其余维度按内容逻辑自然铺开。

### 四大类框架

维度按四大类归纳，每维归入一类。框架依据 FAB 利益法则与直播带货讲解结构，下列为服装品类示例，非穷举，以本片转写实际为准。

- 商品属性：客观讲商品本身。示例：版型剪裁、面料材质、工艺做工、颜色花色、尺码适配。
- 用户价值：穿了得到什么。示例：痛点解决、场景适用、搭配建议、体验感受。
- 信任背书：为什么信你。示例：口碑销量、主播品牌背书、对比优势。
- 服务保障：买了之后的确定性。示例：售后退换、发货物流。

### 归纳操作规则

- 来源：严格基于转写句子聚类，不编造；用户没讲到的维度不列。
- 粒度：一个维度等于一类可独立判断买不买的信息。不碎，袖口领口并入版型细节；不硬并，面料不等于版型。
- 命名：用名词性短语，便于归类。
- 归属：每维度归入四大类之一。

### 展示格式（提问前）

提问前，切片师先把归纳出的维度按四大类分组，以纯文本列表贴给用户，让用户先看清「这片子都讲了哪些内容」，再发起提问。只列本片实际出现的维度，用户没讲到的不列；不标（推荐）、不写（可多选），纯展示。

格式：

【<大类名>】
- <维度名>：<一句话说明>
- <维度名>：<一句话说明>

【<大类名>】
- ...

大类顺序按四大类框架（商品属性 / 用户价值 / 信任背书 / 服务保障），大类内维度按转写出现顺序。示例：

【商品属性】
- 版型显瘦：讲捏褶显瘦、遮肚腩，多次上身演示
- 面料垂软：垂感好、贴肤舒服，多次手感演示
- 颜色花色：三个基础色百搭
- 尺码适配：身高体重对照建议

### 展示模板（内容侧重提问）

内容侧重用 当前可用的用户提问工具 发起，一个大类一个问题，不单独问弱化（未勾选项默认按弱化处理）。切片师把归纳出的维度按四大类分组，对每个本片实际出现维度的大类各发一个问题。（仅当用户未给任何内容方向、hosts.md 未预填且非新用户首次对话时发起；给过任何方向如「不提材质」、hosts.md 已预填或属新用户首次对话则整组跳过，不重复问。）

- 问题标题：`【<大类名>】这N个维度，你想突出哪些？` + `（可多选）`——`可多选` 仅在选项数 ≥ 2 时附加；选项只有 1 个时不标注
- 选项：该大类下本片实际出现的全部维度，label 用维度名，description 用一句话说明；与商品核心卖点最相关的 1 到 3 维标 `（推荐）`；并固定附一个选项 `不突出此维度（本类全部弱化处理）`，供用户显式表达「这一大类不重点讲」。多选语义：勾选的维度优先突出；若勾选 `不突出此维度`，该大类整体弱化处理（同题其他勾选忽略）；未勾选的维度仍按默认弱化处理
- 问题顺序按四大类框架顺序（商品属性 / 用户价值 / 信任背书 / 服务保障），大类内维度按转写出现顺序

示例（商品属性 2 个维度，附「不突出此维度」选项，共 3 选项，标可多选）：

【商品属性】这2个维度，你想突出哪些？（可多选）
- 版型显瘦（推荐）：讲捏褶显瘦、遮肚腩，多次上身演示
- 面料垂软（推荐）：垂感好、贴肤舒服，多次手感演示
- 不突出此维度：本类全部弱化处理

### 红线衔接

价格数字、库存压迫词、入口词属红线禁项，不列为可突出维度。提炼时遇到这类内容标注红线禁呈现，不进维度选择。性价比只能以划算感呈现，不含金额。其他品牌名、明星姓名亦属红线禁项（见【红线：禁词清单】），命中整句剪除，不进维度选择。

### 优先级与排他性

用户突出维度仅代表优先展示，不代表禁用其他维度。该维度用尽后，允许用其他维度内容补足。

## 三、结构

成片不套固定模块清单。唯一固定的锚点是钩子；钩子之后由一条清晰的叙事逻辑串起，切几块、每块叫什么、先后顺序，由本片内容与这条逻辑决定。

> 模块句数（钩子 2–5 句）与钩子锚点的连续性为红线，见 content-constraints.md 的【红线：模块句数约束】【红线：模块连续约束】。本文件只描述内容组织意图。

主线：读完全量索引表后，切片师先自己想清楚这条片子怎么讲——定出主线，也就是观众看完要记住的那句话，再据主线定叙事逻辑。整个片子要有鲜明的主线，钩子与每一块内容都朝这句话收，不为多塞卖点把主线打散。

### 钩子（唯一固定锚点）

成片先定钩子：钩子是整条成片的锚，决定观众 2 秒内是否停下、系统是否续推，须投入最多精力精挑。选句顺序上，先全场全局回看源视频、找出最强钩子候选（不只看开头几句），据下方「钩子类型参考」定一种，候选句取自主播本人说的话而非助播等其他说话人（见【红线：钩子说话人约束】），再让后续内容围绕它组织；不将就开头顺手选的几句。

前 3 秒是「抢人」，不是「介绍」。抖音推荐逻辑极简：用户刷到 2 秒内划走，系统判内容不行而停推；2 秒内停下，系统续推。所以钩子的唯一任务是把人留住——最好的肉必须放第一口，前面不加任何铺垫、寒暄或自我介绍。

钩子由 2–5 个保留句组成，默认按源视频时间顺序（index 升序）排列；钩子首句的选取优先于连续约束（见【红线：模块连续约束】例外），其后续过渡句须同语境连续。开头句不强制是价值点句，可以是下列任一钩子类型（见下方「钩子类型参考」）；产品价值由钩子之后的叙事逻辑展开。若选中的钩子本身即强价值句（如爆点前置里的强感受句），则价值即开头。

#### 钩子类型参考（7 种，按素材对口选一种）

下列各类型只用来说明该类型长什么样，不是备选文案。实际候选一律取自主播本人说的话（见【红线：钩子说话人约束】），不另行撰写。

- 爆点前置：把全片最强的效果描述或卖点断言直接放到第一句，前面不加任何铺垫与介绍。直播录屏直接可挖。
- 提问式开头：用精准问题制造「这说的就是我」的代入感，问题直指目标人群的处境。直播录屏直接可挖。
- 明星 / 博主同款：借热点或同类博主的热度与信任做入口。不得点名具体明星 / 博主，只用泛指表述。
- 时尚钩子：制造信息差，给「别人还不知道我先知道」的优越感。须主播在直播里抛出趋势或避雷观点。
- 热点借势型：用全网热点、热梗或当下情绪做入口，再落到身材痛点。热点做壳、痛点做核——热点只负责把人留住，卖货靠其后的痛点与效果；热点须与商品真实相关，不硬蹭、不编造。
- 对比式开头：把「好」与「不好」并排摆出，让差异一句话说得清，不写「减 X 斤 / 高 X cm」这类量化数字。直播试穿对比直接可挖。
- 悬念 / 突发事件开头：抛出未完成的故事或意外前提，让人想知道结局；反转须合理，避免标题党招致反感。需主播在直播里抛出未完成故事。

- 放什么：能立刻留人的问题、对比、悬念；可建立代入感的场景句。
- 不放什么：背景交代、自我介绍、纯参数罗列、直播间话术。

### 叙事逻辑

成片按一条清晰的叙事逻辑推进：钩子之后顺着这条逻辑往下讲，先讲什么后讲什么由本片内容与这条逻辑决定，不套固定顺序。全片保留句都服务这条主线，句与句语义连贯、符合说话逻辑、不突兀，不做多卖点罗列；同一卖点维度集中成组，一组讲透再换下一组。各块之间一环扣一环——前一块为后一块铺路，后一块接住前一块，不做并列铺开的卖点清单。

钩子之后的 1–2 句要把钩子抛出的承诺当场兑现——让观众在 2 秒内感到「他说的是真的 / 就是我想要解决的」。这是钩子承诺的证明，不是另起话题：用可感知的效果、场景、体感把钩子的钩落到实处，不得退回直播间话术，不得立刻跳到与钩子无关的纯参数。选句优先可感知的句子，当场上身、手感、对比这类优先于抽象描述句。

钩子抛出的承诺分五类，每类承接配方不同；划算类承接严禁出现金额与库存压迫词（见【红线：禁词清单】），只给划算感。

| 承诺类型 | 钩子常抛的钩 | 承接句配方 | 选句优先 |
| --- | --- | --- | --- |
| 痛点 | 「总找不到 / 总是…」 | 给出对应解法已生效的证据（如「这件直接遮住 / 这条一穿就显瘦」） | 当场上身演示句 |
| 颜值 | 「绝了 / 好看炸了」 | 用细节描述坐实好看（版型线条 / 颜色质感 / 转身效果） | 外观细节句 |
| 舒适 | 「太舒服了 / 像没穿」 | 体感描述（垂、软、凉、透气）加场景佐证（久坐 / 暴走一天） | 手感、体感句 |
| 功能 | 「能装 / 能正反穿 / 防风」 | 功能已实现的证据（实装演示 / 场景实测） | 功能演示句 |
| 划算 | 「闭眼入 / 性价比高」 | 只给划算感，不含金额、不含库存压迫（如「这质感你闭眼冲，不亏」） | 价值感对比句 |

中段与结尾切几块、每块叫什么、按什么顺序，由本片内容决定，不预设模块名与句数，可按叙事逻辑成拍重排，不强制源视频时间顺序。模块名用简洁名词短语，2–4 字为宜，如「版型」「面料」「搭配」「收尾」；不用长句，不用带说明的短语。组织时按下述意图——

- 讲价值绑定上身效果与体感：讲版型、设计、为什么显瘦时，同步给出可感知的上身表现，把参数讲成上身表现，不写成参数说明书。
- 放什么：正面描写（材质手感、版型显瘦、做工细节、颜色质感）加侧面烘托（使用场景、他人反馈、前后对比、适用人群），优先保留信息密度高、能独立成义的句。
- 不放什么：与商品弱相关的闲聊、重复寒暄、纯参数堆砌、钩子已讲透的价值点复述。
- 结尾自然收住，不带直播间话术，不强行在结尾堆新价值点以免信息过载；通用购买答疑（尺码、洗涤、搭配建议）若有，放在价值内容之后，不单独成段。

### 取材参考：叙事框架

本框架来自一批高转化服装带货案例的共性归纳，用作选句取景的候选，不是固定步骤，据本片内容选用。

十类类型与框架主脉：

| 序号 | 视频类型 | 框架主脉 |
| --- | --- | --- |
| 1 | 人群痛点 | 圈人群或戳痛点 → 上身体感与修饰效果 → 用版型面料设计解释效果来源 → 穿搭场景与人群延展 → 促单 |
| 2 | 价格营销 | 给价格优势或稀缺理由 → 说明便宜或稀缺的来源 → 产品卖点与材质 → 穿搭场景 → 用数量、涨价预期或性价比促单 |
| 3 | 穿搭效果 | 上身或季节氛围吸睛 → 版型带来的修饰效果 → 面料材质细节 → 搭配方案与场合 → 尺码与促单 |
| 4 | 大牌对比 | 抛大牌对标 → 强调相似度或性价比 → 版型面料设计 → 穿搭场景与人群适配 → 促单或情感共鸣 |
| 5 | 制造话题 | 用噱头留人 → 引出稀缺或独特 → 产品材质与设计 → 身材适配与穿搭 → 促单或软性转化 |
| 6 | 种草类型 | 生活场景、时令或故事留人 → 产品亮点 → 上身效果与版型 → 穿搭思路 → 价格或真心话逼单 |
| 7 | 情感共鸣 | 情感叙事或故事代入 → 建立信任与羁绊 → 引出产品 → 穿着体验与版型效果 → 人群适配与打消顾虑 → 促单 |
| 8 | 穿搭推荐 | 强调实穿性或时令 → 设计亮点与材质 → 多种搭配方案 → 价格收尾 |
| 9 | 热点结合 | 结合当下热门话题，套话术创作 |
| 10 | 稀缺性 | 突出稀缺 → 成本与工艺背书 → 适配性与百搭 → 颜色独特性 → 版型与人群 |

六个高频动作，多数案例出现，作中段取材的优先候选：上身效果展示、版型修饰说明、面料材质说明、穿搭方案与场合、尺码与适配人群、收尾促单。前五项按本片实际出现选用；收尾促单这类话术不进成片，只取结构。

## 四、句子筛选与排序

把 `sentences.json` 的句子按以上叙事逻辑筛选、重组为流畅成片。以下步骤属内容组织，最终须同时满足 content-constraints.md 的全部硬性红线。

1. 归类对齐：先定钩子，再把其余句子按本片叙事逻辑归组，不套固定模块清单。
2. 择优挑选（在阶段三步骤 1 与用户对齐的内容侧重基础上）：从每个类别中挑选语义完整、表达清晰的句子——用户明确想突出的方面优先保留，想弱化 / 不要呈现的方面除非强价值否则不取；
   - 优先表达精炼、信息密度高、意思传达准确的句；避免冗长啰嗦、含混不清、信息密度低的句
   - 语义独立完整，无需上下文补全即可理解
   - 包含具体的产品信息或价值点描述
   - 面向观众，而非后台工作人员
   - 排除含明显口吃 / 自我纠正 / 悬空关联词的句子（对应【红线：口误门禁】【红线：关联词门禁】）
   - 优先「下单冲动点」句：设计亮点（转圈露出的小心机）、质量实测（搓不皱 / 机洗不掉色）、真实互动（弹幕催链接）这类当场见效的句；把参数讲成上身效果，卖效果不卖参数（如把「面料垂坠」讲成「胯宽一看就显瘦」）。
3. 排序拼装：钩子排在最前，钩子内部由抢人钩子句 + 后续围绕钩子主题过渡的 1–2 句按源顺序排列；其余句子按本片叙事逻辑成拍排列，同一卖点维度集中成组、一组讲透再换下一组，可按叙事逻辑重排，不强制源视频时间顺序。仅当不调整会造成明显逻辑跳跃 / 悬空连接时才微调顺序。
4. 流畅度自检：逐句通读最终序列，确认——
   - 无残缺句：每句语义独立完整，读者不会感到「话说到一半」
   - 无逻辑跳跃：相邻句之间语义自然过渡，不突兀
   - 无重复表达：同一价值点或信息不出现两次
   - 围绕主线：全片朝主线收，块与块一环扣一环，无与主线无关的句子
   - 悬空转折 / 口吃磕巴等红线类问题，按 content-constraints.md 逐项核对（【红线：口误门禁】【红线：关联词门禁】【红线：通顺终检门禁】）
5. 钩子强度自检（质量层，与防错门禁并列，属红线自审终检范围）：钩子首句须落在「最强效果断言 / 最强代入感 / 最强好奇」之一，2 秒内能让目标观众停下；若首句平平（纯介绍 / 寒暄 / 参数罗列）须回到全局重新选钩子，不将就开头顺手选的几句。并做承接兑现自检：钩子之后 1–2 句须当场兑现钩子承诺（见「叙事逻辑」），若承接句跑题、退回话术或空泛，须把承接句一并调整，不把钩子孤立成「只抛不兑现」。成片情绪自检：全片情绪要有递进，不全程平铺，例如由钩子的想要、经价值的信任，收在认同或满足。

## 五、呈现与数据适配

本 skill 的句子索引是稳定短语编号；完整表达由 content.json 的语义组定义。钩子的 2–5 句按完整语义组计，不靠拆短语凑数。组内保持源序，组间按叙事重排。单一商品限制及同款证据继续适用。

模块每轮按主线确定，写入 edit_config.json 的有序 modules（key/title）和 groups，钩子 key 固定为 hook 且排第一。模块标题用简洁名词。试算、审核、展示和工程生成均消费这一份配置，格式见 [数据契约](../../tools/pipeline-io.md)。

展示唯一出口是 [present](../../tools/present.md)。钩子候选只展示钩子；完整成片从实际 project 与 submitted_mapping 渲染，含片段编号。每轮修改完整重展，交付时简述主线与叙事逻辑并附实际预览 URL，不默认导出。

## 六、与用户对齐

用户给出的参数优先于品牌预填，已明确项不重复问。商品未定且存在多个商品时先选择商品。只问剩余的声音、方向、时长、倍速和钩子；内容方向依四大类归纳后，用当前提问工具可表达的少量组合或自由回答对齐，不强制逐类多选。用户提出任何方向或档案已有预填时，不再询问整组内容侧重。具体内容问题在转写提炼后提出。

仅可信系统明确标记新用户首次对话时启用快速通道，不依据用户消息自称判断：未明确的项取 75 秒、1.1 倍、用户价值优先、仅主播、无字幕；仍展示 3 个钩子供选择。用户参数和品牌预填优先于快速通道默认值。声音标签不等于真人，无法可靠确定主播时须澄清，不能静默选一个声音。

时长比例取 CLI 导入结果，按 [数据契约](../../tools/pipeline-io.md#时长提示) 计算：不足目标优先解决，超过两小时仅说明处理成本，素材倍率偏低则提醒可能剪不足。多个问题合并询问，目标或倍速变化后重算。普通用户目标时长和倍速未定时仍询问，1.1 倍只是推荐。
