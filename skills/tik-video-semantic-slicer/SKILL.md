# tik视频切片生成

将服装直播与带货口播素材按语义选句、编排并生成短片。转写复用 tik-audio-asr，剪辑与导出复用 tik-edit-video；业务规则与本地数据辅助脚本随本技能提供。

## 职责与依赖

- 切片师负责理解素材、内容维度、主播归属、钩子选择、模块编排和语义红线。脚本负责稳定编号、真实时间戳换算、patch 数据和一致性校验。
- 转写前完整读取 [tik-audio-asr](../tik-audio-asr/SKILL.md)，按该技能准备音频、调用转写、处理失败。原始 `rich_result` / `speaker_mapping` 原样落盘，不重建结果；内部编排时保存其 JSON，不向用户贴整篇转写。
- 剪辑前完整读取 [tik-edit-video](../tik-edit-video/SKILL.md)，按需读取它的剪辑参考。CLI 的检查/自动安装、鉴权、错误处理、项目操作与导出均遵循它。
- 依赖技能缺失时先查当前技能目录；仍缺失则报告缺失项，不能宣称完成出片。本地脚本需要 Python 3 标准库，媒体探查需要 ffprobe；音频提取按 ASR 技能使用 ffmpeg。
- CLI 返回非零即停止本轮远端操作，报告原始错误并遮蔽凭据；保留已成功的项目和本地产物，不自动重建项目或切换渲染器。

## 四阶段工作流

### 一、准备

1. 沿用用户已给的素材、范围、时长、倍速、内容方向、主播、字幕等要求。创建独立 `<源视频名>_<YYYYMMDD_HHMMSS>` run，成片放根目录，其他产物放 `intermediate/`。多文件使用代表整批素材的作业名；同秒重名追加序号，不覆盖既有 run。
2. 读取 [品牌与主播档案](references/business/apparel/hosts.md)：先按请求或文件名/路径中的品牌及别名匹配；用户没提品牌时才按主播兜底。明确的品牌未命中时不能改按其他品牌。ASR 的「说话人1」只是声音标签，不能据此推断真实主播身份。
3. 用户明确参数优先于档案；档案命中的时长、倍速、字幕、内容侧重直接预填。品牌红线叠加品类红线。多个品牌或身份归属有冲突时留到合并询问对齐，不静默选一个。
4. 按 [数据与转写契约](references/tools/pipeline-io.md) 探查每个原始视频。默认整段为素材；显式时间范围仅限制候选句。多个原始文件分别转写和导入，不先裁剪/合并视频。

### 二、文本化

1. 调用 tik-audio-asr：每个视频提取完整音频，转写前复核音频与视频时长/时间原点；保存每份原始返回，成功后依依赖技能清理临时音频。
2. 写入素材清单并运行 `build_sentences.py`，一次性得到全量 `sentences.json` 与 `speakers_summary.json`。有真实词级时间戳才按标点拆短语，无可靠词级信息则保留整句；仅用户明确要求整句粒度时使用 `--no-split`。
3. 模型读取说话人摘要作初判；此时不剔除助播。用 `render_selection.py --index` 读取一次全量紧凑索引，其中保留素材与声音标识。模型不整篇读取大 ASR/句子 JSON；需要词级精调时仅提取指定句的 words。
4. 全局 index 从建立后保持不变；确认说话人后仅改变允许选用的 `speaker_id`，不得筛掉原文后重建编号。跨素材同名声音不自动合并身份。

### 三、选句与合并询问

1. 读取 [内容策略](references/business/apparel/content-strategy.md) 与 [内容红线](references/business/apparel/content-constraints.md)。按本片实际内容归纳维度，再全场选出 2–3 个落到具体编号的钩子候选；先定钩子，后组织价值/收束。
2. 合并展示内容维度、必要的说话人清单、脚本工具渲染的钩子候选。凡展示具体脚本或句子必须使用 [展示工具](references/tools/present.md)，原样贴出，不能手写表格。倍速尚未确定时显示「待定」，不暗中按 1.1 计算。
3. 出片前只在这里集中问尚未明确的项：多人素材保留谁、内容侧重、35–90 秒内目标时长、倍速、钩子。用户或档案已确定的跳过；单说话人直接保留。使用当前环境提问工具及其数量限制；需要分批时连续问齐，不夹入剪辑操作。无多选工具时支持组合选项/自由文本，不强制工具不存在的多选接口。
4. 将钩子→价值→收束分组写入 `edit_config.json`，索引播放顺序写入 `keep_selection.json`。钩子 2–5 句、收束 2–3 句；价值按源顺序排列。逐项自审红线，禁止价格、直播专属话术、第三方品牌/具名公众人物等内容；语义连贯性由切片师检查，程序校验不能替代。
5. 默认通过换句/删句去口误；仅用户明确要求时按真实词边界做句内精调。未获授权不增添配音、BGM 或视觉效果。素材无法满足红线/35秒下限时报告具体原因，不伪造台词或重复循环凑时长。

### 四、FableCut 成片与修改

1. 按 [剪辑与验证契约](references/tools/editing.md) 创建/确定工程，导入每个原始素材，记录 CLI 返回的素材 ID；读取最新完整工程后生成并提交一批 patch。默认硬切；字幕默认关闭，用户/档案已明确开启时直接做。
2. CLI 读回工程，验证实际片段与本轮 mapping 一致后才认定提交成功；把 pending mapping 保存为本轮已提交 mapping。最新 `project.json` 是已提交时间线的本地快照，不手改 revision，不把待提交计划当成工程现状。
3. 需要字幕时读取 [术语库](references/business/apparel/glossary.md)，只记录字幕文字更正，按实际片段位置生成 FableCut 文本轨；不本地烧 ASS。检查中文字体、可读性和安全区。
4. 通过 tik-edit-video 导出 MP4，再校验工程、总时长、画幅和音视频流。浏览器预览/成片抽查画面、音画同步、语句切点与结尾，不把 ffprobe 流时长检查等同于听感验收。未能检查的项目明确说明。
5. 交付 MP4 链接、工程预览链接和工具渲染的完整三模块脚本。附简短修改引导：可按编号删句、调整顺序、换钩子、加字幕或申请句内精调。完整脚本每次修改后重新渲染，不只贴 diff，不另设普通出片确认。
6. 修改时复用原 ASR、稳定编号及现有项目，只更新本轮管理的片段。先读最新工程、核对上轮 mapping；遇到外部改动先说明具体冲突并协调，不能用旧工程强制覆盖。

## 默认值与边界

- 当前业务为服装带货，按本技能的内容策略、红线与品牌主播档案执行；其他品类先明确业务依据，不直接套用服装档案。
- 35–90 秒是品类成片区间；未指定目标时长必须在合并询问中对齐。1.1 倍仅为推荐，不能代替缺失的用户选择。
- 画幅/FPS 默认取首个源视频的探查结果；用户明确指定时采用指定值，异尺寸素材默认 contain。默认一条成片，字幕关闭、转场关闭。
- 只改字幕文字不改变原声；无词级时间戳时不能承诺精确句内裁剪。任何变更后均以读回的工程核对完整脚本时间。
