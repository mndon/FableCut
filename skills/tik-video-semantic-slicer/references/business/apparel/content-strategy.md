# 内容策略（内容逻辑与结构）

本文件是切片师在「阶段三 选句」时的业务指南：规定成片统一采用的内容策略（唯一一套，无多选项），描述内容逻辑、叙事结构、择优与排序。硬性红线（禁词清单、时长、关联词、口误等数值与判定规则）的权威定义见 content-constraints.md，本文件不重复其条文，只在相关处用【红线：标签名】指向。

切片师读 `present --index` 渲染的全量索引表后，先在阶段三归纳本片内容维度（见下方「内容维度归纳规则」），再在阶段三合并询问里与用户对齐「想突出 / 想弱化哪些方面」（内容侧重，仅当用户未给任何内容方向时发起）。用户的侧重作为选句与排序的首要优先级输入，仍须满足全部硬性红线。策略支持按内容逻辑重构排序。

## 一、内容取舍原则

目标：把视频剪成一条「让人看了想买、且买得明白」的带货短片——从用户能体验到的价值出发，讲清为什么值得买。

- 适用场景：电商带货、商品讲解、种草引流；目标是让观众产生「我也想要」的代入感，而非单纯罗列参数。
- 优先保留：用户可体验的感受/获益、具体使用场景、差异化价值、真实反馈。
- 可压低：与卖货弱相关的闲聊、重复寒暄、纯参数堆砌。
- 提炼原则：先提炼最想表达的意思、最吸引人的点；精简聚焦，宁可多切几段也不要一段塞太多。

## 二、内容维度归纳规则

本规则供阶段三内容侧重归纳与提问使用。切片师据本规则把本片转写聚为内容维度，先按下方「展示格式（提问前）」把归纳结果原样贴给用户看（中性罗列本片讲了哪些内容维度），再按「展示模板（内容侧重提问）」在阶段三合并询问里用 当前环境的提问工具 问用户想突出哪些；仅当用户未给任何内容方向时才发起（给过方向则整组跳过，不重复问）。用户的选择作为选句与排序的首要优先级输入。

### 四大类框架

维度按四大类归纳，每维归入一类。框架依据 FAB 利益法则与直播带货讲解结构，下列为服装品类示例，非穷举，以本片转写实际为准。

- 商品属性：客观讲商品本身。示例：版型剪裁、面料材质、工艺做工、颜色花色、尺码适配。
- 用户价值：穿了得到什么。示例：痛点解决、场景适用、搭配建议、体验感受。
- 信任背书：为什么信你。示例：口碑销量、主播品牌背书、对比优势。
- 服务保障：买了之后的确定性。示例：售后退换、发货物流。

### 归纳操作规则

- 来源：严格基于转写句子聚类，不编造；用户没讲到的维度不列。
- 粒度：一个维度等于一类可独立判断买不买的信息。不碎，袖口领口并入版型细节；不硬并，面料不等于版型。
- 命名：用名词性短语，便于归类。
- 归属：每维度归入四大类之一。

### 展示格式（提问前）

提问前，切片师先把归纳出的维度按四大类分组，以纯文本列表贴给用户，让用户先看清「这片子都讲了哪些内容」，再发起提问。只列本片实际出现的维度，用户没讲到的不列；不标（推荐）、不写（可多选），纯展示。

格式：

【<大类名>】
- <维度名>：<一句话说明>
- <维度名>：<一句话说明>

【<大类名>】
- ...

大类顺序按四大类框架（商品属性 / 用户价值 / 信任背书 / 服务保障），大类内维度按转写出现顺序。示例：

【商品属性】
- 版型显瘦：讲捏褶显瘦、遮肚腩，多次上身演示
- 面料垂软：垂感好、贴肤舒服，多次手感演示
- 颜色花色：三个基础色百搭
- 尺码适配：身高体重对照建议

### 展示模板（内容侧重提问）

内容侧重用 当前环境的提问工具 发起，一个大类一个问题，不单独问弱化（未勾选项默认按弱化处理）。切片师把归纳出的维度按四大类分组，对每个本片实际出现维度的大类各发一个问题。（仅当用户未给任何内容方向时发起；给过任何方向如「不提材质」则整组跳过，不重复问。）

- 问题标题：`【<大类名>】这N个维度，你想突出哪些？` + `（可多选）`——`可多选` 仅在选项数 ≥ 2 时附加；选项只有 1 个时不标注
- 选项：该大类下本片实际出现的全部维度，label 用维度名，description 用一句话说明；与商品核心卖点最相关的 1 到 3 维标 `（推荐）`；并固定附一个选项 `不突出此维度（本类全部弱化处理）`，供用户显式表达「这一大类不重点讲」。多选语义：勾选的维度优先突出；若勾选 `不突出此维度`，该大类整体弱化处理（同题其他勾选忽略）；未勾选的维度仍按默认弱化处理
- 问题顺序按四大类框架顺序（商品属性 / 用户价值 / 信任背书 / 服务保障），大类内维度按转写出现顺序

示例（商品属性 2 个维度，附「不突出此维度」选项，共 3 选项，标可多选）：

【商品属性】这2个维度，你想突出哪些？（可多选）
- 版型显瘦（推荐）：讲捏褶显瘦、遮肚腩，多次上身演示
- 面料垂软（推荐）：垂感好、贴肤舒服，多次手感演示
- 不突出此维度：本类全部弱化处理

### 红线衔接

价格数字、库存压迫词、入口词属红线禁项，不列为可突出维度。提炼时遇到这类内容标注红线禁呈现，不进维度选择。性价比只能以划算感呈现，不含金额。其他品牌名、明星姓名亦属红线禁项（见【红线：禁词清单】），命中整句剪除，不进维度选择。

### 优先级与排他性

用户突出维度仅代表优先展示，不代表禁用其他维度。该维度用尽、成片仍不达时长要求时，允许用其他维度内容补足。

## 三、结构

成片叙事固定为钩子 → 价值 → 收束 三模块。钩子按时间顺序排列；价值全部严格按源视频时间顺序（index 升序）排列；收束按内容逻辑（答疑在前、收束句在后）组织。下面分别说明各模块放什么、不放什么。

> 模块句数（钩子 2–5 句、收束 2–3 句）与末句的硬约束为红线，见 content-constraints.md 的【红线：模块句数约束】【红线：收束约束】。本文件只描述内容组织意图。

### 钩子

成片先定钩子：钩子是整条成片的锚，决定观众 2 秒内是否停下、系统是否续推，须投入最多精力精挑。选句顺序上，先全场全局回看源视频、找出最强钩子候选（不只看开头几句），据下方「钩子类型参考」定一种并精修，再让价值 / 收束 围绕它组织；不将就开头顺手选的几句。

前 3 秒是「抢人」，不是「介绍」。抖音推荐逻辑极简：用户刷到 2 秒内划走，系统判内容不行而停推；2 秒内停下，系统续推。所以钩子的唯一任务是把人留住——最好的肉必须放第一口，前面不加任何铺垫、寒暄或自我介绍。

模块由 2–5 个保留句组成，默认按源视频时间顺序（index 升序）排列；钩子首句的选取优先于连续约束（见【红线：模块连续约束】例外），其后续过渡句须同语境连续。开头句不强制是价值点句，可以是下列任一钩子类型（见下方「钩子类型参考」）；价值点由价值模块展开。若选中的钩子本身即强价值句（如爆点前置里的强感受句），则价值点即开头。

后续 1–2 句围绕钩子主题自然过渡：可继续放大钩子抛出的好奇/对比/悬念，或顺势引出产品价值点；不得立刻跳到与钩子无关的纯参数，也不得退回直播间话术。

#### 钩子类型参考（6 种，按素材对口选一种）

- 爆点前置：把全程视觉冲击力最强的 3 秒（模特转身、裙摆扬起、面料光泽）直接怼到第一秒，前面不加任何东西；配卡点重音 BGM，第一拍落在惊艳画面上。直播录屏直接可挖。
- 提问式开头：用精准问题制造「这说的就是我」的代入感（如「你们是不是总觉得自己没合适衣服参加重要场合？」）。口播 / AI 配音语气像朋友聊天，字幕问题打屏幕正中加粗，问完停顿 0.5 秒再接画面。直播录屏直接可挖。
- 明星 / 博主同款：借热点或垂类博主的热度与信任（如「小红书 10 万博主都在穿的这条裤」）。需热点 / 授权素材；速度是第一位，热点 48 小时内发布效果最佳，画面做同款视觉对比。（不得点名具体明星 / 博主，只用泛指表述）
- 时尚钩子：制造信息差，给「别人还不知道我先知道」的优越感（如「今年夏天最火的 4 种裙子你知道几种？」）。需主播在直播里抛出趋势 / 避雷观点；快剪 + 字幕条清单体，每趋势 2–3 秒。
- 对比式开头：把「好」与「不好」放一起让差异肉眼可见（如「左边普通白裤，右边我们这条，你自己看」）。须配合画面，最经典是穿前 vs 穿后分屏，画面打大字「显瘦 10 斤 / 显高 5cm」量化差异。直播试穿对比直接可挖。
- 悬念 / 突发事件开头：制造未完成故事让人想知结局（如「这条裙子差点上不了架，原因你想不到」）。AI 朗读带紧张感，悬念在前 3 秒抛、第 4–8 秒揭晓；反转须合理，避免标题党招致反感。需主播在直播里抛出未完成故事。

- 放什么：能立刻留住人的画面 / 问题 / 对比 / 悬念；可建立代入感的场景句。
- 不放什么：背景交代、自我介绍、纯参数罗列、直播间话术。

### 价值

讲清产品好在哪、建立信任与渴望。覆盖颜色、材质、版型、做工、搭配等产品价值描述。

- 放什么：正面描写（材质手感、版型显瘦、做工细节、颜色质感）+ 侧面烘托（使用场景、他人反馈、前后对比、适用人群）。优先保留信息密度高、能独立成义的句；维度可按源中出现顺序自然成块。
- 不放什么：与商品弱相关的闲聊、重复寒暄、纯参数堆砌、钩子已讲透的价值点复述。

排序约束（全文件仅此处定义一次）：价值模块内所有句子严格按源视频时间顺序（index 升序）排列。

### 收束

- 模块由 2–3 个保留句组成，自然收尾，不带直播间话术（不得含入口词/直播语境词/库存压迫词，见【红线：禁词清单】）；且须取自源视频同一语境段内连续的句子（允许跳过中间口误/废话，不得跨大段跳选，硬性见【红线：模块连续约束】）。
- 放什么：可选前置通用购买答疑（尺码、洗涤、搭配建议，如「身高 160 体重 90 穿 S 就够」）放在收束句之前作实用信息；末句作价值重申。
- 收束句（末句）必须落在价值认同上（硬性见【红线：收束约束】）；不得与钩子使用相同句子——若以价值收束，须换一种表达复述价值，不得原句照搬。
- 不放什么：纯尺码/物流/购买答疑不得单独作为收束；不强行在结尾堆新价值点，避免信息过载。

## 四、句子筛选与排序

把 `sentences.json` 中处于指定素材范围且属于已确认保留说话人的句子按以上叙事逻辑筛选、重组为流畅成片。以下步骤属内容组织，最终须同时满足 content-constraints.md 的全部硬性红线。

1. 归类对齐：将句子按钩子 → 价值 → 收束 三模块归类，不再另设多套分类。
2. 择优挑选（在阶段三步骤 1 与用户对齐的内容侧重基础上）：从每个类别中挑选语义完整、表达清晰的句子——用户明确想突出的方面优先保留，想弱化 / 不要呈现的方面除非强价值否则不取；
   - 优先表达精炼、信息密度高、意思传达准确的句；避免冗长啰嗦、含混不清、信息密度低的句
   - 语义独立完整，无需上下文补全即可理解
   - 包含具体的产品信息或价值点描述
   - 面向观众，而非后台工作人员
   - 排除含明显口吃 / 自我纠正 / 悬空关联词的句子（对应【红线：口误门禁】【红线：关联词门禁】）
3. 排序拼装：模块顺序固定钩子 → 价值 → 收束。钩子由抢人钩子句 + 后续围绕钩子主题过渡的 1–2 句按时间顺序排列；价值内部严格按源视频时间顺序（index 升序）排列（规则见上文「结构 · 价值」）；收束由通用答疑（若有）+ 收束句按内容顺序组成。仅当不调整会造成明显逻辑跳跃 / 悬空连接时才微调顺序。
4. 流畅度自检：逐句通读最终序列，确认——
   - 无残缺句：每句语义独立完整，读者不会感到「话说到一半」
   - 无逻辑跳跃：相邻句之间语义自然过渡，不突兀
   - 无重复表达：同一价值点或信息不出现两次
   - 悬空转折 / 口吃磕巴等红线类问题，按 content-constraints.md 逐项核对（【红线：口误门禁】【红线：关联词门禁】【红线：通顺终检门禁】）
5. 钩子强度自检（质量层，与防错门禁并列，属红线自审终检范围）：钩子首句须落在「最强画面 / 最强代入感 / 最强好奇」之一，2 秒内能让目标观众停下；若首句平平（纯介绍 / 寒暄 / 参数罗列）须回到全局重新选钩子，不将就开头顺手选的几句。

## 五、呈现格式

阶段三向用户展示候选保留句 / 最终脚本时，必须按模块分组，每模块一张表，表头固定为 `| 编号 | 源时间 | 秒 | 成片时间 | 文本 |`。表格由 `present` 工具（scripts/render_selection.py）确定性生成（候选传 `--hook` 与已知倍速；完整脚本传 `--config` 和 `--selection`，出片后再传 `--project` / `--mapping`），切片师原样贴出其输出，不手写。多轮调整时，每一轮都须按此格式完整重渲染全部模块行（不展示增量 diff）；出片后以工程为时间线依据，表格忠实展示工程。（注：选句初期的钩子候选展示步是例外——此步只传 --hook 展示钩子，不提前提供价值 / 收束的完整方案；完整多模块展示用于阶段三选句完成后或出片后修改重展。）

模块集合（钩子 / 价值 / 收束及其标题、播放顺序、句数约束）由 `scripts/modules.json` 定义；下文三表为该配置下的示例。调整标题或句数约束时修改该文件并同步业务文档；更改模块结构还须同步选择配置和相关业务校验。

- `编号`：该句在 `sentences.json` 中的原始 index
- `源时间`：素材 ID 和对应原文件中的秒数区间，保留毫秒精度；出片后取自实际 clip 源窗口
- `秒`：源区间 end - start，保留毫秒精度；是红线核查用列（片段时长软偏好 1–7s）
- `成片时间`：草稿按已知倍速/转场计算，倍速未定则显示待定；出片后直接取工程 clip 的 start 与 start+duration，包含精调/转场的实际结果
- `文本`：句子原文

> 模块顺序固定钩子 → 价值 → 收束；展示即按此三表依次呈现给用户确认。钩子表可填 2–5 行、收束表可填 2–3 行，钩子首行须为抢人钩子句（可不限于价值点）、收束末行须为价值收束句。分组是流动的内容判断，每轮据用户反馈重新定，保存在 edit_config.json 的 groups，不固化进 `keep_selection.json`；本轮分组写入 edit_config.json 的 groups，渲染时把本轮配置传给 present 工具即可。

## 工具衔接

上述提问使用当前环境实际提供的工具，遵守其单次问题数和选项限制；没有多选能力时用组合选项或自由文本承接多个维度，不把单选结果当作多选。用户已明确的参数与本轮已答项不重复问。

多素材的 index 按用户提供的素材顺序、各文件内源时间递增排列；每条句子保留 source_id。钩子/收束的同语境连续性须检查素材归属，不能仅凭跨文件相邻编号判定连续。脚本只能复用录音已有表达，不生成配音、补写台词或擅自添加 BGM/视觉特效。
