# 内容约束（成片红线与 LLM 输出规范）

本文件是切片师在「阶段三 选句」时须强制满足的硬性红线与 `keep_selection.json` 输出规范，是全部数值与判定规则的唯一权威。内容逻辑、叙事阶段分类、择优挑选与排序指引见 content-strategy.md，本文件不展开；凡策略文件用【红线：标签名】指向的规则，均以此处为准。

# 一、结构性红线

## 【红线：模块句数约束】
- 钩子由 2–5 句组成。
- 收束由 2–3 句组成。
- 价值句数不限；价值模块内全部严格按源视频时间顺序（index 升序）排列。

上述强制数值由 `scripts/modules.json` 的 `min` / `max` 字段驱动，`build_edit_ops.py` 调用共享的选择校验函数据此自动校验；如需调整句数上限，修改该 JSON 并同步本业务约束中的说明。

## 【红线：模块连续约束】
钩子 2–5 句、收束 2–3 句，各自须取自源视频同一语境段内紧邻的连续句子（相邻 index 自然成块）；允许跳过句中夹带的口误 / 废话 / 重复（依据【红线：口误门禁】已剔除），但不得跨大段跳选（如从开场钩子句直接跳到结尾收束句）拼出割裂观感。若素材在该模块所需位置确存在断层、无连续句可选，须在【红线：通顺终检门禁】中确认整体仍连贯后方可放行。

例外（钩子强度优先）：钩子首句（抢人钩子句）的选取优先于本条连续约束——若全场最强钩子句附近无足够连续好句可凑满 2 句，允许钩子首句独立选取（可来自不同语境段），仅其后续过渡句须与首句同语境连续。收束仍须整段连续（收束连贯性优先于钩子）。

## 【红线：收束约束】
收束末段必须落在价值认同上，让整片收在价值上。尺码等通用购买答疑若有则放在收束句之前，无则直接以价值认同收束，不强行添加；纯尺码/物流/购买答疑不得单独作为收束。若以价值认同收束，须换一种表达复述价值，不得与钩子使用相同句子原句照搬。

# 二、内容红线

## 【红线：禁词清单】
成片不得出现以下内容，命中即整句剪除或换用不含该内容的中性表述——

1. 直播间专属表述
   - 入口 / 交互动作类：切片后无对应入口的，如「一号链接 / 链接 / 上车 / 灯牌 / 点点关注 / 左上角」等；
   - 直播专属语境类：「直播 / 直播间」；
   - 库存压迫类（与商品属性无关的销售压迫）：如「库存不多了 / 还有几件 / 拍下还有货 / 现货秒发 / 仓库发货 / 补货 / 断码 / 卖完无补」等。
   - 售后承诺类（与商品本身内容无关的直播间服务承诺）：如「运费险 / 运运险」等。
2. 价格与金额：任何商品价格数字——具体金额、数字标价、到手价、原价 / 折扣价、优惠券面额等（如「99 元」「到手 79」「原价 199」「券后 59」）。
3. 品牌与人物名
   - 其他品牌名：非本商品的第三方品牌（含竞品、上下游、联名方），无论褒贬；
   - 明星 / 具名公众人物姓名：具体明星、艺人、知名博主、网红的真实姓名或广为人知艺名，含「某某明星」「某博主」等具名指代。

## 【红线：关联词门禁】
每个被选中句都必须能独立成句、语义完整，不得是依附于其他句子的半句。尤其注意关联词（转折 / 因果 / 条件 / 递进 / 并列类，如「而且 / 但是 / 所以 / 因为 / 虽然 / 既…又 / 不仅…还 / 如果…就」等）必须成对出现或自身前后完整——不得只出现转折后半（如仅「但是……」而无前面的条件 / 铺垫）、不得只出现「因为…」而无「所以」、不得只出现「虽然…」而无后半、不得只出现条件 / 让步 / 递进的前半而无后半。规则：凡含关联词的句子，必须同时选中能承接该关联词句式的其他句子，整组一并入选；若找不到可承接的前置 / 后续句，则该句不得使用，改用不含关联词的句子替代。不得出现「只有而且……却没有前文」「只有但是……却无铺垫」这类悬空关联词。

## 【红线：近义重复门禁】
不得连续选用两句语义高度近似的句子（如「面料质感很好」+「面料质感超好」），避免复读感与啰嗦。若两条句意重叠，只保留一条信息密度更高 / 表达更完整的，另一条废弃或换用讲不同维度的句子。

## 【红线：口误门禁】
必须剔除口吃 / 口误片段——即一句话内重复开头、说话卡壳、自我纠正的不完整片段（如「就像炼丹就像太上老君炼丹炉出来的感觉」中「就像炼丹」为口误，应整段去除该口误部分）。凡含明显口误的句子，须削去口误片段后再评估；若削后语义残缺则整句废弃，不得带口误进入成片。择优挑选阶段即应排除含口吃 / 重复开头 / 自我纠正的句子（呼应 content-strategy.md 择优挑选），除非用户已明确要求句内精调，且能用真实词级时间戳削去口误后保持精炼、语义完整。默认选句阶段换用无口误的句子。

# 三、时长与倍速约束

## 【红线：成片总时长约束】
最终保留片段拼成的成片总时长须介于 35 秒与 90 秒之间（由阶段一设定的硬下限与硬上限）。自然筛选后总时长 < 35s 则补充保留句至 ≥ 35s，> 90s 则删减保留句至 ≤ 90s（优先删冗余或弱价值句）。此约束统筹全局，优先于下方单片段时长约束。

## 【偏好：片段时长约束】
单个片段按所选短语的源时长 `end - start` 计，建议控制在 1 秒至 7 秒之间；上下限均为软偏好，非强制——`build_edit_ops.py` 仅对超出范围的短语作软提醒，不拦截，交由切片师判断是否保留。
- 上限（软偏好）：单段建议不超过 7 秒；若某句或某段超出，优先换用更短的句子、或将其拆为多段分别保留；确属强价值、无法替代的超长句也可保留，软提醒仅作提示。
- 下限（软偏好）：短于 1s 的碎片（单字 / 极短语气词 / 半截关联词）优先不选入，优先换用更完整、时长达标的句子，或先与相邻句合并后再整体评估；若素材中仅余不足 1s 的碎片，宁可跳过该素材段。确需保留的强价值短片段可放行。

## 【红线：倍速约束】
成片倍速参数化，默认 1.1，合法区间 0.25–4。倍速由用户或品牌档案确定后写入 edit_config.json 的 speed；build_edit_ops 生成各 clip 的 props.speed，tik-edit-video 提交至工程。导出与出片后展示/校验读取最新 project.json，不另传倍速。1.1 是推荐值，未得到用户或档案指定时不可静默采用。数据契约见 [pipeline-io.md](../../tools/pipeline-io.md)。

# 四、终检红线

## 【红线：通顺终检门禁】
完成筛选后须反复通读整条成片脚本，确认同时满足全部前述约束且整体通顺流畅、无逻辑跳跃、无残缺句、收束不跨段割裂（钩子首句依「模块连续约束」例外可独立选取，其后续过渡句仍须同语境连续）。凡命中任一门禁须主动纠正（调索引或替换句子）直至全部通过，才输出 `keep_selection.json`。

# 五、输出规范（keep_selection.json）

严格按以下 JSON 结构输出，不要添加额外内容：

```json
{
  "template": "内容策略",
  "keep_indices": [15, 41, 48, 49, 52, 93]
}
```

- `template`：固定为内容策略
- `keep_indices`：被选中句子的原始 `index` 值数组，按最终成片应有的播放顺序排列。索引值不必升序

输出前还须校验：
- 索引有效性：逐个确认 `keep_indices` 中的值在 `sentences.json` 中真实存在，剔除越界 / 无效索引
- 索引去重：无重复 index，同一句不应出现两次
- 选中句核对：逐条回看 `keep_indices` 指向的句子文本，确认与内容方案意图一致——无漏选关键句、无误选残缺句（尤其悬空转折、关联词残缺的半句、孤伶短语）
- 依赖完整性：若某选中句依赖前置句（悬空连接、因果链、问答对、对比结构），确认对应句也在 `keep_indices` 中
- 规模核对：`keep_indices` 长度与内容方案的句数 / 时长预期大致吻合，偏差过大需回到筛选重新评估

若没有可用句子满足要求，返回空数组 `"keep_indices": []`。
